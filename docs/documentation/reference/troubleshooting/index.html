Troubleshooting and recovery

Choose a safe next step for a missing archive, stale metadata, failed scan, Reader-unavailable EPUB, or interrupted edit.

On this page

Start with the least invasive action

#
  1. Read the full error and check which archive, file, or resource it names. Keep the message and any reported backup path.
  2. Check that the drive is connected, the folder still exists, and files are accessible in Windows Explorer. Wait for an active scan or write to finish before retrying.
  3. Use the symptom-specific action below. Retry once the cause has changed; do not repeatedly submit an outdated metadata or cover preview.
  4. Before repair or manual recovery, close Archeion and copy the complete archive, including hidden files, to a separate safe location. Preserve reported EPUB recovery copies too.
Preserve the sidecars

Do not delete or rewrite live .archeion files as a first-line fix. They hold reading progress, annotations, and Library data that cannot be recreated simply by scanning EPUBs. See Archive storage for data ownership and maintenance effects.

An archive is marked missing

#

Reconnect a removable drive or restore the folder if it has not moved. If you moved it, use Archive Manager → Open archive to open the new location. Verify that the EPUB folders and hidden .archeion folder moved together and that progress and annotations are present.

Only then use Forget on the obsolete archive-list entry. Forget removes a remembered location; it does not delete the archive folder. An archive scan cannot locate a folder at a different path or recreate deleted EPUB files. If the folder was deleted, restore your complete backup before reopening it. See Open or create an archive.

A title, author, or cover is out of date

#

First check Details and the path to ensure you are looking at the intended EPUB. In Settings → Storage, choose Archive scan → Run when the Library has not caught up with an external file change.

If parsed title or author data is still stale, choose Source metadata → Re-extract. It clears cached scan state and scans again; it does not write new values into the EPUB or delete favorites and progress. To change embedded values, use Metadata and covers.

For stale generated artwork, choose Generated cover cache → Clear. Covers are extracted again when needed, and embedded EPUB artwork is not changed. If cover writeback already succeeded but refreshing the cover reported a warning, do not assume the file write failed. See the maintenance reference before choosing a broader repair.

A scan or diagnostic refresh fails

#

Check the error, drive access, file permissions, and whether another program is moving or editing the archive. Keep the archive open in the Library, wait for active scanning to finish, and retry Archive scan → Run. A scan checks files and refreshes Library data; it does not edit EPUB contents.

Use Scanner cache → Clear for suspect cached scan state, then run an Archive scan. If corrupted archive sidecars are reported and retry still fails, back up first and choose Archive metadata → Repair. Repair recovers or rebuilds sidecars when possible, clears scan state, and rescans. It cannot recreate lost annotations without valid saved data.

In Duplicates or EPUB Issues, use Try again after an initial failure or Refresh after a later failure. Previously shown findings can remain alongside a refresh error. They do not prove the new check completed. See archive-health refresh behavior.

An EPUB cannot open in Reader

#

Check whether the EPUB is missing in Details. Locate or restore the file before removing its metadata. If the file exists, enable EPUB Issues, read its diagnostic issues, and note the affected resource path.

Archive metadata repair does not repair the EPUB's internal package, chapter documents, reading order, or encrypted resources. Obtain a readable replacement from your source or restore a known-good EPUB copy. Work on a separate copy if an external EPUB editor is needed, then rescan and refresh diagnostics. An empty diagnostic result is not a promise of full Reader compatibility.

After replacing a book, review annotations in the Reader. Records that cannot reconnect remain detached for review, copy, export, recovery, or removal; do not delete them merely because the new EPUB opens. See changed EPUBs and annotations.

A metadata or cover edit fails

#

If the source changed since the preview, stop the external edit and reopen the editor to review the latest EPUB. For a changed cover image, choose it again and prepare a fresh preview. The stale-source safeguard refuses unsafe replacement rather than silently overwriting newer changes.

Read the failure outcome: the original may be unchanged, the backup may have been restored, or the message may say automatic restore failed. Successful writes can also report a cleanup or cover-refresh warning; check the actual outcome before writing again.

  1. If restoration failed, stop writes and cleanup. Record the reported backup path and original EPUB path, then close Archeion.
  2. Copy the reported recovery file and the complete archive to a separate safe location. Do not use EPUB writeback backup cleanup while investigating.
  3. Inspect a separate copy of the recovery EPUB. After preserving both the current file and the backup, restore the verified copy to the original EPUB location with Windows Explorer, using the normal .epub extension. Do not overwrite the only surviving copy.
  4. Reopen the archive, run an Archive scan, and check the book and its annotations. If the recovery copy is absent or unreadable, use your independent archive backup or obtain a replacement; automatic restoration is not guaranteed.

Optional retained copies from successful edits are separate from the emergency path reported by a failed write. See EPUB writeback backups for retention and cleanup limits.

Settings or archive data cannot load

#

For a temporary Settings load failure, select Retry in the same Settings window after resolving drive or access problems. Archeion attempts interrupted-write recovery when loading saved data. Corrupt application settings are preserved before defaults are used; archive-list and archive-sidecar recovery use valid saved copies where available. These are different safeguards, not a guarantee that all earlier values can be restored.

For persistent errors, preserve the complete archive and relevant application data before further intervention. Record the installed version from About, the exact message, and the failing task when reporting an issue through About and resources. EPUB paths, exported annotations, and sidecar files may contain private information; review anything you share.
